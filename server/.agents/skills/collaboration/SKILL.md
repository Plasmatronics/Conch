# Collaboration

Choose the smallest useful topology: work in one session for tightly coupled or short tasks; use an isolated subagent for a self-contained result; use persistent collaborators only for three or more independent streams or work requiring cross-round coordination. Use the host's native collaboration support when available; otherwise preserve the same decomposition sequentially.

The lead owns decomposition, interfaces, integration, and substantive decisions. Before delegation, split work into self-contained, file-disjoint tasks with explicit ownership, paths, output, and contract boundaries. Do not let multiple workers edit the same file.

Workers should stay within assigned ownership, escalate ambiguity, communicate with peers only for explicit interface dependencies, finish their deliverable, and stop. Route mechanical work to efficient capacity when available, standard implementation to the normal default, and architectural or security-sensitive work to the strongest available reasoning level. Do not bake provider-specific model names into durable instructions.

Avoid delegation for work a single session can finish quickly, vague assignments, overlapping ownership, and unowned architectural decisions.
